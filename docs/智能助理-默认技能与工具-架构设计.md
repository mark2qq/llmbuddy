# 默认技能与默认工具：注册、自动加载与冲突策略

> 版本 1.0.12 · 代码 `core/assistant/bundled.py`（注册表）、`core/assistant/defaults.py`（匹配）、
> `core/assistant/skills.py`（落盘）、`core/assistant/agent.py`（装配）、
> `client/ui/pages/assistant_page.py`（展示）。
> 目标：把 WorkBuddy 那套「装好就有的基础能力」搬进 llmBuddy —— 用户不必先去技能市场找、
> 也不必每轮手动挂载；系统按本轮需求自动加载合适的默认技能，同时保持**可预测、可关闭、可审计**。

---

## 1. 三个概念，别混

| 概念 | 定义 | 谁负责 |
|------|------|--------|
| **默认技能**（default skill） | 随安装包落地、frontmatter 带 `builtin: true` + `auto_load: true` 的技能包（15 个，见 §3.3） | `bundled.py` 出内容，`skills.install_default_skills()` 落盘 |
| **默认工具**（default tool） | 内置工具（文件 / 命令 / 网络 / 技能四组），`Tool.meta.default = True`，**常驻下发**，不需要挂载 | `tools.ToolRegistry._register_builtin()` |
| **自动加载**（auto load） | 每轮对话开始前，用本轮用户原文本地匹配技能，命中就把该技能的执行要求注入 system，并把它建议的工具排到 schema 最前 | `defaults.select()` + `agent.start_turn()` |

一句话：**默认 = 装好就有；自动加载 = 按需求取用；两者都不需要用户点任何按钮。**

## 2. 注册方式

### 2.1 默认技能：代码注册 + 文件落地

单一来源是 `core/assistant/bundled.py` 的 `DEFAULT_SKILLS`（slug / 名称 / 描述 / 触发词 /
建议工具 / 优先级 / 正文）。启动时 `Assistant.__init__` → `skills.ensure_builtin_skills()`
→ `install_default_skills()` 把每个技能写成：

```
%LOCALAPPDATA%\llmBuddy\assistant\skills\<slug>\SKILL.md
```

SKILL.md 由 `bundled.skill_md(slug)` 生成，frontmatter 是**匹配算法的数据源**：

```yaml
name: doc-writer                 # slug，技能唯一标识（也是 skill_run 的名字）
description: 按需求写出结构清晰…  # 一句话说明「什么时候用」
tools: [fs_read, fs_write, …]    # 该技能建议使用的工具（只用于排序与提示）
version: 1.0.0
builtin: true                    # 系统自带：升级时允许覆盖
bundle_version: 2                # 默认技能包版本（升级判据）
auto_load: true                  # 参与「按需自动加载」候选池
priority: 45                     # 同分时的优先级（大者先）
triggers: [写文档, 写报告, 周报]  # 命中即加分（中文子串匹配，无需分词）
```

**升级语义（重要）**

| 磁盘现状 | 行为 |
|---|---|
| 目录/SKILL.md 不存在 | 落盘（首次安装或用户删掉后自动补回） |
| 有 `builtin: true` 且 `bundle_version` < 代码里的 `BUNDLE_VERSION` | 覆盖为新版（老用户升级时自动补齐触发词等新字段） |
| 有 `builtin: true` 且版本相同或更高 | 不碰（幂等，二次启动零写盘） |
| **没有** `builtin: true`（用户自建的同名技能） | **绝不覆盖**（数据安全红线，有用例守着） |

> 想改默认技能的写法：复制成新 slug 再改（例如 `doc-writer-mine`）。直接改默认技能正文，
> 下次升 `BUNDLE_VERSION` 会被系统版覆盖——这是刻意的，避免「默认能力」在各台机器上漂移。

### 2.2 让用户自己装的技能也参与自动加载

任意技能的 frontmatter 加两行即可，不需要改代码：

```yaml
auto_load: true
triggers: [月报模板, 经营分析]
```

可用 `priority` 调同分时的抢占顺序（默认 0，默认技能包是 20~45）。

### 2.3 默认工具：注册即默认

`ToolRegistry._register_builtin()` 注册完 14 个内置工具后统一打标：

```python
tool.meta["default"] = True          # UI 打「默认」标；文档用
tool.meta["group"] = "文件|命令|网络|技能"
```

下发逻辑**不看**这个标记（下发只由 `disabled / allow / max_tools` 决定），它的作用是：
① 前端清单中心能显示「默认」与分组；② 测试与文档有稳定断言点。

## 4. 自动加载的触发条件

**时机**：`Assistant.start_turn()` 里，记录用户消息之后、组装 messages 之前，**每轮**算一次。
**成本**：纯本地计算（一次读已装技能的 frontmatter，15 个文件 < 10ms），无网络、无模型调用。

判定链（任一不满足即不加载）：

| # | 条件 | 不满足时的行为 |
|---|------|----------------|
| 1 | `config.auto_load == true`（总开关，默认开） | 本轮不加载 profile，也不加载默认技能 |
| 2 | 用户**没有**手动挂载技能（`mounted_skills` 为空） | 见 §5 规则 ①：用户选择一票否决 |
| 3 | **没有**命中 profile（`profiles.match_profile()` 返回 None） | 见 §5 规则 ②：profile 优先 |
| 4 | `config.auto_skill_limit > 0`（默认 2，上限 4） | 为 0 时只关掉默认技能匹配，profile 照常 |
| 5 | 技能在候选池里：`auto_load: true` 且不在 `config.auto_skill_off` | 逐个技能被跳过，不影响其它技能 |
| 6 | 得分 ≥ `MIN_SCORE = 3` | 不加载（宁缺勿滥，避免污染 system） |

得分公式（`defaults.score_skill`）：

```
score = 触发词命中数 × 3      （最多计 3 个 → 封顶 9 分，防止「文档」这类高频词拉爆）
      + 技能名 token 命中 × 2  （doc-writer → doc / writer，被原文提到才加分）
      + 描述片段命中 × 1       （描述按标点切段取前 6 字做子串，最多 2 分）
```

排序：`分数↓ → priority↓ → slug↑`（**确定性**：同样的输入永远同样的输出，便于复现与测试）。
产出：`{"skills": [slug…], "matched": {...}, "scores": {...}, "limit": n}`。

## 5. 优先级规则（从高到低）

```
① 用户手动挂载的 skills        ← 底栏 [技能] 菜单勾选，最高优先，一票否决
② 命中的 profile              ← profiles.py：技能 + 工具白名单的成组配置
③ 默认技能自动匹配             ← 本轮默认 2 个
④ L3 降级：已装技能清单        ← 写进 system，让模型自己决定 skill_run
```

落地位置：`agent.start_turn()` 先算 `profile`，再算 `auto = _auto_defaults(...)`；
`_auto_defaults` 里 `if mounted or profile is not None: return {}` —— ① ② 命中时
③ 直接不参与，`_skills_hint()` 的四分支也互斥，保证**同一轮只有一套技能指令**。

### 5.1 内置 profile 一览（`profiles.py`，命中即有工具白名单）

| id | 名称 | 触发词（示例） | 技能 | 工具白名单 |
|----|------|----------------|------|-----------|
| `file-organize` | 文件整理 | 整理 / 归档 / 分类 / 清理目录 | workspace-organizer | fs_list, fs_read, fs_info, fs_mkdir, fs_move, fs_glob, skill_run |
| `code-read` | 代码阅读 | 代码 / 仓库 / 技术栈 / 架构 / 体检 | repo-digest | fs_list, fs_glob, fs_grep, fs_read, fs_info, skill_run |
| `code-detail` | 代码审查（1.0.12 新增） | 代码审查 / 看看这段代码 / 有没有 bug / review | code-review | fs_read, fs_glob, fs_grep, fs_list, skill_run |
| `web-research` | 网页调研 | 网页 / 链接 / 抓取 / 调研 / url | web-brief | web_fetch, fs_write, skill_run |

> `code-detail` 是把「审一段代码」从「体检整个仓库」里拆出来的：老配置里
> `code-read` 的触发词「代码 / review」会把片段级审查也吞掉，挂上 `repo-digest`
> 答非所问。老用户升级时 `ensure_builtin_profiles()` 会**补上**缺失的 id，不用手动加。

注入内容的差异：

| 命中 | system 里的段落 | 是否给正文 |
|------|----------------|-----------|
| profile | `## 本轮指定技能`（profile 自带 slug） | 否（让模型 `skill_run`） |
| 用户挂载 | `## 本轮指定技能`（用户勾的 slug） | 否 |
| 默认技能 | `## 本轮自动加载的默认技能` + `### 技能要点（首个技能）` | **是**（正文摘录 ≤900 字） |
| 都没有 | `## 可用技能` 清单 | 否 |

为什么要给正文：默认技能的意义是「不用配就能干」，如果还要模型先 `skill_run` 一轮，
本地小模型极易反复 `skill_list` 空转（1.0.11 用户截图里的 107 步）。给摘录 = 一次到位；
长尾细节仍可通过 `skill_run` 拿完整流程。

## 6. 冲突处理策略

| 冲突场景 | 处理 | 理由 |
|----------|------|------|
| 用户挂载了技能，本轮又命中了默认技能 | **用户挂载生效**，默认技能不加载 | 显式意图 > 系统推断 |
| 命中 profile，同时命中默认技能 | **profile 生效**，默认技能不加载 | profile 带工具白名单，两套指令会互相稀释 |
| 默认技能建议的工具被用户禁用 | 技能照常加载，system 明确写「X 已被用户禁用，请改用可用工具」 | 禁用是安全约束；让模型知道边界，别反复试 |
| 默认技能建议的工具超出 `max_tools` 上限 | 用 `prefer` 把这些工具**排到最前**（只调顺序，不增不减） | 宁可裁掉边缘 MCP，也不让技能缺工具 |
| 两个技能分数相同 | `priority` 大者先；再相同按 slug 字典序 | 确定性，便于复现 |
| 用户自己装了同名技能（slug 与默认包撞车） | 磁盘上**不覆盖**；技能列表里它照常可用 | 用户数据优先 |
| 用户不想用某个默认技能 | `config.auto_skill_off: ["doc-writer"]`（PUT `/profiles`） | 比删文件更可逆，升级也不会回来 |
| 用户完全不想自动加载 | `auto_load: false`（[技能] 菜单里可一键切） | 老行为：不加载 profile、不加载默认技能、不写清单 |
| 技能与任务其实无关（误命中） | 只注入「执行要求」，**不限制**模型动作，也不裁剪工具 | 误命中的代价是几百 token，不是任务失败 |

> **不裁剪工具**是刻意设计：1.0.11 的 profile 已经会按需求收窄白名单，默认技能再裁一次，
> 就会出现「命中『写文档』→ 只剩 5 个工具 → 顺带要做的事做不了」的失败。用户明确要求
> 「不影响任务执行的准确性」，所以默认技能只做两件事：注入执行要求、把工具排前面。

## 7. 稳定性设计

| 措施 | 说明 |
|------|------|
| 全程 try/except 降级 | 技能目录不可读、frontmatter 坏、`bundled` 导入失败 → 返回空结果，本轮对话照常 |
| 幂等落盘 | 已是最新的默认技能零写盘；`prune_backups()` 只留 5 份 `.backup-<ts>` |
| 原子安装 | 默认包复用既有 `_atomic_install` 路径语义（临时目录 + 备份 + replace） |
| 确定性排序 | 分数 / priority / slug 三级排序，测试可固定断言 |
| 上限硬约束 | `auto_skill_limit` clamp 到 `0..4`；单轮注入正文 ≤900 字，避免吃满上下文 |
| 不碰用户数据 | 非 `builtin` 的同名技能永不覆盖；`auto_skill_off` 只改配置不删文件 |
| 审计 | 落盘写 `audit("default_skills_installed", slugs, version)`；开关变更写 `auto_load_updated` |
| 与旧行为兼容 | `auto_load=false` 时 system 不出现任何新段落；老客户端忽略 `auto_loaded.source` 等新字段 |

## 10. 怎么加一个默认技能（30 秒版）

1. 打开 `core/assistant/bundled.py`，在 `_SKILLS` 里加一条 `_skill(...)`：
   slug、中文名、一句话描述（写清「什么时候用」）、触发词、建议工具、正文（目标 / 执行要求 / 约束）。
2. `BUNDLE_VERSION += 1`（不 +1 老用户拿不到）。
3. 跑 `pytest tests/test_assistant_defaults.py` → 启动一次客户端确认 `[默认]` 出现在技能列表。
4. 不想全量发版也可以让用户手工放：把 SKILL.md 写进技能目录并加 `auto_load: true` 即可。

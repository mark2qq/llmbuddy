# 智能助理 · 空间与提示词 · 架构设计（v1.0.11）

> 配套实现：`core/assistant/store.py`（存储）、`core/assistant/agent.py`（业务）、
> `routers/assistant.py`（HTTP）、`client/ui/pages/assistant_page.py`（左栏导航 + 底栏）。
> 交互与结构对齐 WorkBuddy：左栏「任务 (N) / 空间 (N)」两区，底栏「📝 提示词 / ✨」。

---

## 1. 背景与关键约束

用户原始约束（不可偏离）：

1. **空间功能**：创建、命名、切换、管理多个相互独立的空间，空间之间数据隔离。
2. **提示词功能**：创建、编辑、存储、复用提示词，跨场景快速调用。
3. **关键 bug 修复**：先前在空间内创建任务会**覆盖**之前的任务。一个空间必须能同时承载
   多个相互独立的任务，各任务互不覆盖、可分别查看与切换。
4. 布局与操作方式贴近 WorkBuddy，功能完整、结构清晰、交互一致。

「覆盖」错觉的根因：旧导航只渲染每个工作区**最新一条**任务，用户切到空间后看起来像
「只剩刚建的」。修复方式不是迁移 session 文件，而是让空间行**可展开**显示其全部任务，
且创建新任务只新增一条、绝不改写既有任务（`new_session` 始终 append，主键 `id` 唯一）。

## 2. 空间（Spaces）

### 2.1 数据模型

空间 = 具名、可切换的**工作区目录**，不做 session 文件迁移，任务通过 `workspace` 路径归属。

- 注册表：`spaces/registry.json`（位于 `%LOCALAPPDATA%\llmBuddy\assistant`）
  - 字段：`name`、`order`、`current`、`pinned`（布尔，置顶）
  - `current` 至多一个为 `true`，作为默认活跃空间
- 任务归属：每条 session 自带 `workspace` 字段；空间即「某个 `workspace` 目录」的具名视图。
- 隔离性：不同 `workspace` 目录天然物理隔离；删除空间只清注册表与排序，**不删**目录下任务。

### 2.2 空间列表（`store.space_list`）

返回结构（导航与 HTTP 共用）：

| 字段 | 含义 |
|------|------|
| `path` | 工作区目录绝对路径（归一化） |
| `name` | 空间显示名 |
| `current` | 是否当前活跃 |
| `order` | 排序权重 |
| `pinned` | 是否置顶 |
| `count` | 该空间任务数 |
| `tasks` | **全部**任务列表（按 `updated_at` 倒序，不再只取最新一条） |
| `exists` | 目录是否仍存在（缺失目录标警示，不崩溃） |

合并来源：① 注册表里登记过的空间（含「已登记但暂未建任务」的空空间）；② 有任务但未
登记的空间（自动补登记）。空空间也出现在列表里，避免「建了空间却看不到」。

### 2.3 导航渲染（异步 + 可展开）

```
refresh()
  └─ _apply_sessions() → _fill_spaces()
                           └─ Worker(self._assist.spaces)   # 异步拉 GET /spaces
                              └─ _apply_spaces(spaces)
                                 └─ self._nav_spaces = spaces
                                 └─ _rebuild_nav_tasks()      # 渲染左栏两区
```

- 空间行点击（`_on_space_header`）：切换展开/收起；展开时 `activate_space` 设为当前空间，
  并自动打开该空间**最新**一条任务（`_open_task`）。
- 展开后列出该空间 `tasks` 全部条目（每条约 62px 行高，不裁文字）。
- 收起态：空间行只显示 `名称 (N)`，点行即展开——不再「看起来覆盖了旧任务」。

### 2.4 空间 HTTP 端点（`routers/assistant.py`）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/spaces` | 新建空间（建目录 + 登记注册表） |
| PATCH | `/spaces/{key:path}` | 重命名 / 调整排序 / 置顶 |
| DELETE | `/spaces/{key:path}` | 注销（清登记，保留任务目录） |
| POST | `/spaces/{key:path}/activate` | 设为当前空间 |
| GET | `/spaces` | 列出全部空间（含 `tasks`/`count`/`exists`） |

### 2.5 多任务并行（运行态隔离）

任务运行态在 `TaskRun` 里、不在页面上（`_cur_sid` 事件上下文代理）。同一空间内多个任务
可同时运行，各自 `_stream/_busy/_bubble/_thinking/_proc/_approvals` 互不串台——这与
空间修复同源：空间的「任务」是一等集合，页面只负责**渲染集合**，不持有单例运行态。

## 3. 提示词（Prompts）

### 3.1 数据模型

全局可复用提示词库（**不**按空间隔离，跨空间/跨会话都能调）：

- 存储目录：`prompts/`（位于 `%LOCALAPPDATA%\llmBuddy\assistant`）
- 单条文件：`{id}.json`，`id = "p" + uuid4().hex[:12]`（12 位足够本地唯一、短易读）
- 字段：`id`、`title`、`content`、`created_at`、`updated_at`、`tags`（可选）

### 3.2 存储函数（`store.py`）

| 函数 | 说明 |
|------|------|
| `save_prompt(p)` | 新建或更新（按 `id` upsert，幂等） |
| `load_prompt(pid)` | 读单条 |
| `list_prompts()` | 列出全部（按 `updated_at` 倒序） |
| `delete_prompt(pid)` | 删除单条 |

### 3.3 UI 入口（底栏，对齐 WorkBuddy）

| 按钮 | 对象名 | 行为 |
|------|--------|------|
| `📝 提示词` | `BarChip` `_prompt_btn` | 打开 `_PromptPicker`：从库选一条插入输入框；可跳转「管理提示词库」 |
| `✨` | `GuideBtn` `_enhance_btn` | 把当前输入框文字交给模型润色成更好的提示词（临时会话，不改写原文） |

- 插入规则（`_insert_prompt`）：输入框非空则换行追加（`\n\n`），空则直接写入；光标移到末尾。
- 空输入点 ✨ 给中文提示「输入框是空的，先写点内容再优化吧」，不发起请求。
- 提示词管理对话框 `_PromptManagerDialog`：新建 / 编辑 / 删除 / 复用。

### 3.4 提示词 HTTP 端点（`routers/assistant.py`）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/prompts` | 列出全部 |
| POST | `/prompts` | 新建（`title`+`content`） |
| GET | `/prompts/{pid}` | 读单条 |
| PATCH | `/prompts/{pid}` | 更新（幂等） |
| DELETE | `/prompts/{pid}` | 删除 |

空 `title`/`content` 由后端校验拒绝（测试 `test_http_prompt_rejects_empty`）。

### 3.5 增强提示词模板（1.0.12）

「✨」不是随口润色，而是按固定契约改写。模板单一来源：`_EnhanceDialog._ENHANCE_INSTR`。

**六条改写要求**（对齐 WorkBuddy 的提示词写法）：

1. 明确目标与范围——一句话写清可判定的结果，并界定「做什么 / 不做什么」；
2. 补充必要上下文——角色/输入/已知条件/场景/读者；缺失信息用 `【假设】` 标注，**禁止编造事实**；
3. 添加约束——篇幅、语气、必含要点、禁止项、信息不足时的处理方式；
4. 规范输出格式——交付物形态（Markdown/表格/JSON/清单）+ 固定小节顺序；
5. 去除冗余——删重复表述、空泛形容词、不可验证要求，同类约束合并；
6. 保持原意与原语言——中文进中文出，不新增需求、不删关键条件。

**三段式输出**：`## 一、增强版提示词` / `## 二、主要改动`（三列表格：维度·原文情况·增强后）/ `## 三、待确认`（≤3 条，无则写「无」）。

**「采用」只贴正文**：`_extract_enhanced_prompt()` 只截取第一段，改动表格与待确认留在对话框里，
避免说明文字混进下一轮提问。容错策略：识别不到标题 → 原样返回全文（绝不丢内容）；
自动剥 ``` 围栏与「以下是…：」引导语（两者可能互相嵌套，来回剥两轮）。

| 函数 / 元素 | 位置 | 职责 |
|---|---|---|
| `_ENHANCE_INSTR` | `_EnhanceDialog` 类属性 | 增强指令模板（唯一来源） |
| `_extract_enhanced_prompt(text)` | 模块级 | 三段式 → 纯提示词正文，含降级 |
| `_adopt()` | `_EnhanceDialog` | 取正文写回 `_input`，清理临时会话 |

> 临时会话：点 ✨ 时 `new_session()` 建一个会话，关闭/采用时 `delete_session()` 删掉，
> 不污染用户的任务列表（模型侧仍走正常 chat 链路，不再单独开一套 provider 调用）。

## 4. 底栏布局与宽度门禁

真实窗口最小宽 **1000**、左栏 **200** → 右栏最窄约 **770**。所有底栏按钮（含
`📝 提示词`、`✨`）必须**始终可见且带文字**，不做宽度自适应隐藏。

- 门禁常量：`AssistantPage.BAR_BUDGET_W = 720`（= 770 - 50 边距/抖动/缓冲）。
- 实测：空闲态 542px / 忙碌态（+运行指示/停止/引导）614px，均 ≤ 720。
- 挂载技能 chip：≥3 个（或超预算）时 `_reparent_skill_chips` 把 chip 容器折到输入框上方
  独立一行（规则④），底栏恒不溢出。
- 上下文占用（`ContextMeter`）是**圆环图标**（12 点顺时针，数字进 tooltip），不凭空占宽度。
- 单一来源：`BAR_BUDGET_W` 由页面类定义、测试从类导入，不在测试里硬编码字面量。

## 6. 工具循环熔断与结果展示（1.0.11 同版修复）

用户截图暴露的问题：助理反复调 `skill_list`（「读取技能列表」）空转到上百步，
且「深度思考」与工具结果内容都不显示。

### 7.1 根因
- `DEFAULT_MAX_TOOL_ROUNDS = 0`（不限制轮次），主循环没有任何「原地打转」检测，
  只靠 900s 墙钟 + 手动停止 —— 模型反复调同一工具时可空转上百步。
- 前端 `ProcessLine.set_result(pos, ok)` 只记成功标志，**丢弃 `tool_result.content`**，
  所以技能清单只显示一行「读取技能列表」，看不到内容。
- 空/纯空白 `reasoning` 也会懒建 `ThinkingBlock`，循环里就铺出一堆空的「深度思考」。

### 7.2 修复
**后端（`core/assistant/agent.py`）—— 重复调用熔断**（保留「不设轮次上限」以支持合法
多步任务，改为止步于「无进展」）：
- 每轮取「本轮全部调用的 (name, 规范化 args)」做签名 `round_sig`。
- 判据①：连续 `LOOP_REPEAT_LIMIT=3` 轮签名完全相同 → 立即中止（用户截图场景）。
- 判据②：最近 `LOOP_WINDOW=10` 轮内同签名出现 `LOOP_ALT_LIMIT=6` 次 → 中止（抓 A/B 交替）。
- 中止时下发明确 `error`：「检测到工具「X」被以完全相同的参数重复调用 N 次…已中止」，
  并提示可直接在左侧「技能」面板查看清单。

**前端（`client/ui/widgets/assistant_cards.py` + `assistant_page.py`）—— 完整展示 + 合并**：
- `ProcessLine.set_result(pos, ok, content)` 新增结果正文；`_refresh` 在展开体里渲染
  结果（超 4000 字截断、可选中复制）——技能清单/文件内容都能看到。
- 同签名连续调用不再新起步骤/新起进程行，改为该步 `repeat += 1`，显示「读取技能列表 ×N」。
- `reasoning` 事件空文本不建块；`ThinkingBlock.set_text("")` 已有隐藏逻辑 → 不再留空壳。

### 7.3 测试
- 后端：`test_turn_aborts_on_repeated_identical_tool_call`、
  `test_turn_distinct_calls_do_not_trip_loop_guard`（不误伤合法多步）。
- 客户端：`test_tool_result_content_is_shown_in_process_line`、
  `test_repeated_identical_tool_call_merges_not_piles`。

## 7. 风险与遗留

- 空间删除是「注销登记」语义，不删任务文件；若用户期望彻底删除目录，需另行确认（当前按
  WorkBuddy「空间只是命名视图」的口径，避免误删数据）。
- 提示词库是全局的，不随空间切换隔离；若后续需要「每空间私有提示词」，在 `prompts/` 下
  按 `workspace` 加子目录即可，存储函数与端点已预留扩展位。
- 版本号：客户端 `APP_VERSION`、后端 `state()["version"]`、安装包 `MyAppVersion` 三处统一为
  `1.0.11`。

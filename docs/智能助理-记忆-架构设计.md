# 智能助理 · 长期记忆 架构设计（1.0.12）

> 目标：让助理**跨任务、跨轮次**记住「用户是谁、这个项目有什么约定、上次做到哪」，
> 而不是每次开新任务都从零解释。实现口径对齐 WorkBuddy 的记忆功能，但**全部落在本机
> 纯文本文件**上——不联网、不加密、用户随时能用记事本打开改。

---

## 1. 为什么需要（问题陈述）

| 现状 | 后果 |
|---|---|
| 每轮只带「本次会话的历史」 | 新建任务后，昨天说过的偏好（先给结论、用中文、别动 8000 端口）全丢 |
| 上下文压缩只压**本任务**的旧消息 | 压缩摘要也跟着任务走，跨任务不继承 |
| 用户重复交代偏好 | 每次都要写一大段背景，长任务里还会被挤掉 |
| 默认技能只有「流程」，没有「事实」 | 技能知道怎么写周报，但不知道「本项目的周报要发给谁」 |

结论：需要一层**独立于会话生命周期**的持久文本，并解决三个工程问题——
**注入预算**（别吃满上下文）、**写入时机**（谁来记、记什么）、**可信度**（记的可能是旧的）。

---

## 2. 三层结构

| 层 | 文件 | 作用域 | 典型内容 | 谁写 |
|---|---|---|---|---|
| 全局记忆 | `memory/MEMORY.md` | 所有空间 | 用户偏好（语言/格式/称呼）、长期事实（城市、职业、作息） | 用户 + 助理（`scope=global`） |
| 空间记忆 | `memory/spaces/<slug>/MEMORY.md` | 单个空间 | 项目约定（技术栈、提交规范）、已确认结论（端口、路径、账号结构） | 用户 + 助理（`to=memory`） |
| 工作日志 | `memory/spaces/<slug>/YYYY-MM-DD.md` | 单个空间 · 按天 | 当天做了什么、改了什么、遗留问题 | 助理（`memory_append` 默认目标） |

> 为什么拆「空间记忆」和「日志」：**结论**要短、要稳定、每轮都注入；**流水**会长，
> 只注入最近 1~2 天、且可以随时丢弃。混在一个文件里，几周后注入预算全被流水吃掉。

**为什么没有云记忆**：llmBuddy 是纯本地产品，没有账号体系。WorkBuddy 的「云记忆」
（服务端自动学习画像）在这里无处落地；对应能力由「全局记忆」承担，写入是显式的。

## 3. 数据位置与命名

```
%LOCALAPPDATA%\llmBuddy\assistant\memory\
    MEMORY.md
    spaces\
        llm-service-1a2b3c\
            MEMORY.md
            2026-10-28.md
```

- 空间目录名 = `可读目录名-路径哈希前 6 位`（`memory._slug`）：
  两个同名目录（`D:\a\src` 与 `E:\b\src`）不会串到同一份记忆；
- 目录名里只保留 `\w-.`，中文保留（`项目A-9f3c21`），其余替换成 `-`；
- **升级安装包不碰这两个目录**（不属于默认技能包，也不在 `dist` 里）；
- 路径解析在调用时进行（`space_dir()` 读模块级 `SPACES_DIR`），测试可直接重定向。

## 4. 注入（读侧）

### 4.1 时机

`agent.start_turn → _build_messages()` 里，拼完系统提示与技能段之后追加：

```python
system += memory.build_hint(session.workspace, enabled=cfg["memory_enabled"])
```

**用任务自己的 `workspace`**，不是全局工作区——同一台机器上 A 空间的任务不该读到
B 空间的约定。

### 4.2 预算

| 常量 | 值 | 作用 |
|---|---|---|
| `MAX_GLOBAL_CHARS` | 2400 | 全局记忆注入上限 |
| `MAX_SPACE_CHARS` | 1600 | 空间记忆注入上限 |
| `MAX_LOG_CHARS` | 1200 | 每天日志注入上限（再按一半给最近两天） |
| `MAX_LOG_DAYS` | 2 | 只带最近两天日志 |
| `MAX_HINT_CHARS` | 6000 | 整段硬上限（三块加起来） |

超限处理：截断 + 显式标注「记忆超出注入预算，已截断；完整内容用 memory_read 读」——
**让模型知道信息不全**，避免它拿半句话当完整结论。

### 4.3 格式

```markdown
## 记忆（本机长期记忆，跨轮次生效）
### 全局记忆（跨空间）
## 用户偏好
- 2026-10-20 回答先给结论，再给依据

### 空间记忆（llm-service）
## 项目约定
- 2026-10-25 提交信息用中文

### 最近工作日志
#### 2026-10-27
- 14:20 把 8000 端口让给网关，助理改用 8021 备端口

记忆只是**过往结论**，可能与当前事实不符：……（核实提醒）
本次对话若产生了值得长期保留的偏好、约定或结论，用 `memory_append` 记一条……
```

两处刻意设计：

1. **模板脚手架不进提示词**：模板里的 `# 全局记忆` H1、`>` 说明行、`<!-- 例如：… -->`
   注释都被 `_body_only()` 过滤——它们写给**人**看，进 system 只是白烧 token；
2. **带「可能过时」的免责与核实要求**：记忆是事实缓存，不是事实本身。端口、版本、
   文件路径这类会变的东西，要求模型先用工具核实，避免拿三天前的结论直接答。

## 5. 写入（写侧）

### 5.1 三条写入路径

| 路径 | 触发 | 落点 | 形状 |
|---|---|---|---|
| 助理主动记 | 模型认为「值得长期保留」时调 `memory_append` | 默认当天日志 | `- HH:MM 内容`（多行缩进两格） |
| 整理成结论 | 模型调 `memory_append` 且 `to=memory` | 空间/全局 `MEMORY.md` | `- YYYY-MM-DD 内容` |
| 用户手改 | 输入框右键「记忆…」→ 对话框保存 | 三个文件任选 | 原文（整体覆盖，上限 2 万字符） |

### 5.2 什么时候该记（写进 system 的口径）

写「**会长期有用、下次还成立**」的东西：

- 用户偏好与称呼、语言与输出格式；
- 项目约定（技术栈、目录约定、提交规范、环境变量名）；
- 已确认的**结论**（选型决定、踩过的坑、哪个端口被谁占用）；
- 用户明确的「以后都这样」。

**不写**：一次性的临时内容、可以从文件里再查到的原文、密码 / 密钥 / 身份证号
（system 里也明说了）。

### 5.3 落盘语义

- 追加，不覆盖（`append_log` / `append_memory` / `append_global`）；
- 首次写入自动带模板（让人打开文件时有结构可循），模板只写一次；
- 原子写：先写 `.tmp` 再 `os.replace`，中途崩溃不会留下半截文件；
- 单条上限 2000 字符、单文件上限 2 万字符（防模型把整篇文档塞进来）。

## 6. 工具定义

| 工具 | 风险 | 参数 | 说明 |
|---|---|---|---|
| `memory_read` | low | `scope=space\|global\|log`、`date` | 读空间记忆 / 全局记忆 / 某天日志；`scope=log` 不带 `date` 返回可读日志清单 |
| `memory_append` | medium | `text`、`scope=space\|global`、`to=log\|memory`、`date` | 默认写本空间当天日志；`to=memory` 写 MEMORY.md |

- 两者都是**默认工具**（`meta.default=true`、分组「记忆」），装好即下发；
- 写入定 `medium`：`readonly_auto` 策略下仍需用户确认——记忆会跨轮次影响后续行为，
  等同于「改配置」，不该静默发生；`yolo` 下自动执行但留审计；
- 工具返回体里带落盘路径，模型可以告诉用户「记到哪了」，用户能自己去核对；
- 作用域用的是 **registry 的 workspace**（= 当前任务的空间），不是模型传的路径，
  模型无法借记忆工具写到沙箱外。

## 7. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/assistant/memory?workspace=` | 快照：`{enabled, workspace, global{path,text}, space{path,text}, logs[{date,path,text,chars,preview}], stats}` |
| PUT | `/api/v1/assistant/memory` | body `{workspace, scope, date?, text}`；`text=""` 即清空（保留文件） |

错误码：`2050` 缺 text / 2051 超长 / 2052 没工作区 / 2053 未知 scope / 2054 写入失败。
每次保存都写一条审计 `memory_save`（scope / path / chars），便于回溯「谁把约定改掉了」。

`/state` 里另有 `memory: {enabled, workspace, global_chars, space_chars, logs, log_chars}`，
只给体量、**不下发正文**（避免每次刷新都传几万字）。

## 8. 界面

**入口**：输入框右键 →「记忆…」（与「插入提示词…」并列；底栏不放按钮，遵循 1.0.8
「底栏只有三个胶囊」的宽度门禁）。

**对话框**（`client/ui/widgets/memory_dialog.py`）：

```
┌ 记忆 ─────────────────────────────────────────────┐
│ 本机 Markdown 记忆 · 自动注入：开 · 当前空间 llm-service │
│ ┌──────────┬────────────────────────────────────┐ │
│ │全局记忆   │ C:\...\memory\MEMORY.md            │ │
│ │空间记忆   │ ┌────────────────────────────────┐ │ │
│ │2026-10-28│ │ # 全局记忆                      │ │ │
│ │ 日志     │ │ ## 用户偏好                     │ │ │
│ │2026-10-27│ │ - 回答先给结论                  │ │ │
│ │ 日志     │ └────────────────────────────────┘ │ │
│ │          │ ● 未保存 · 96 字   [清空][保存][关闭] │ │
│ └──────────┴────────────────────────────────────┘ │
│ 已保存（96 字）                                    │
└───────────────────────────────────────────────────┘
```

- 左列表：全局 / 空间 / 最近 14 天日志（今天没记录也占一行，方便补记）；
- 右编辑器：纯文本 + 路径 + 字数；改动未保存时标题前加 `● 未保存`；
- 保存走 `Worker`（后台线程 PUT），完成后回一行「已保存（N 字）」并触发 `refresh()`，
  左栏/菜单里的体量立刻更新；
- 失败不静默：状态行显示「保存失败：<原因>」；
- 切条目时先把编辑器内容 stash 回条目，**不丢未保存的改动**（`dirty_keys()` 只报真改过的）。

## 9. 冲突与稳定性

| 场景 | 处理 |
|---|---|
| 记忆与当前事实冲突（端口改了） | system 里明确要求「先用工具核实」，记忆只作线索 |
| `memory_enabled=false` | 不注入、`build_hint` 返回空串；文件保留，随时可再开 |
| 记忆文件被用户删了 | 读成空串，正常跑；下一次写入自动重建模板 |
| 文件被改成非 UTF-8 | `_read` 兜异常 → 空；（建议用户用 UTF-8 编辑，记事本默认即 UTF-8） |
| 目录不可写（只读盘/权限） | 写入返回 False → 工具报「写入记忆失败」，界面显示「保存失败」，**不影响本轮对话** |
| 记忆把上下文吃满 | 三层字符预算 + 整体 6000 上限 + 截断标注 |
| 模型滥写记忆 | 单条 2000 字上限 + `medium` 风险需审批（`readonly_auto` 下逐条确认） |
| 与默认技能/profile 的关系 | 互不干扰：技能管「怎么做」，记忆管「已知事实」；两者都进 system 的不同小节 |
| 与上下文压缩的关系 | 压缩只动 `session.messages`，**从不动记忆文件**；记忆不参与摘要计算 |

## 10. 测试覆盖

`tests/test_assistant_memory.py`（18 例）：

- 空记忆不占提示词；日志按天追加（同一天累加、多行缩进、标题只出现一次）；
- 空间/全局记忆首次带模板、二次追加不重复；`snapshot` 结构；
- `build_hint` 三块齐全、模板脚手架不进提示词、`enabled=false` 返回空、超长截断；
- 两个工具：注册 / 风险级 / 分组 / `meta.default` / 真实落盘 / 空参数拒绝 / 空记忆读取不报错；
- 配置：`memory_enabled` 默认 True 且能读回 False；
- 接口：GET/PUT 三种 scope + 四种错误码；
- Agent 端到端：记忆真的进了 system；关掉开关后不进。

`client/ui_tests/test_memory_dialog.py`（7 例）：条目结构、切换保内容、dirty 只报改动、
保存回调、无改动不发请求、失败可见、空记忆仍可写、输入框右键有「记忆…」。

## 12. 30 秒上手

1. **看**：输入框右键 →「记忆…」，三条条目就是全部内容（都是本机 Markdown）；
2. **改**：直接编辑 →「保存」，下一轮对话立即生效（不用重启）；
3. **让它自己记**：正常聊，说「这个项目的提交信息用中文，记一下」，它调
   `memory_append` 写进本空间日志；要沉淀成长期结论时说「写进项目约定」；
4. **关掉**：`config.json` 里 `memory_enabled: false`（或后续版本在设置页给开关），
   记忆不再注入，文件仍在。
